\section{Limitaciones y tareas de cierre}
No se declara el avance completo. La demostración local valida funcionalidad
de ambos motores; la carga anual aporta volumen y trazabilidad de aire. Ninguna
de las dos, por separado o sumando sus resultados, resuelve automáticamente
todas las preguntas del enunciado.

\begin{enumerate}
\item Mantener la ruta canónica SQL y reunir evidencia anual actualizada; las
consultas anuales y de staging ya están separadas y probadas.
\item Acreditar los datos observados para PG07. MG04/MG05/MG08 ya tienen
implementación v2: confirmar su ejecución y la aceptación académica de la regla
demo, replay local y accidentes de otro año, sin presentarlos como datos oficiales de 2025.
\item Confirmar la aceptación académica de alternativas por canal lógico y datos demo.
\item Verificar los informes de ambas fuentes v2 y la interpretación geográfica;
no mezclar su conteo con la generación anual v1.
\item Confirmar la ejecución remota del CI, que ya invoca la suite offline,
y repetir las pruebas sobre la versión candidata.
\item Revisar modelos, evidencias, referencias y redacción entre todos los integrantes.
\end{enumerate}

La recuperación histórica conserva un checkpoint de 83/85 pruebas con dos
SQLite no idénticos y trece respuestas históricas faltantes. Ese pendiente se
mantiene separado de las pruebas nuevas y no se transforma en PASS al aprobarlas.
No impide escribir y probar código independiente.

\section{Conclusiones parciales}
PostgreSQL permite representar relaciones y validar coherencia mediante claves,
restricciones y consultas SQL. MongoDB permite conservar lecturas con metadatos
variables y procesarlas mediante filtros y pipelines. La integración depende
de un contrato compartido y validaciones de aplicación, no de una FK entre motores.

La ruta SQL canónica quedó restaurada y diferenciada del núcleo de práctica.
El principal trabajo pendiente es acreditar los datos y las consultas faltantes.
La evidencia de volumen y las pruebas locales son
avances verificables, pero no deben presentarse como cierre de todos los requisitos.
El procesamiento distribuido y la interfaz se abordarán en la entrega final.
